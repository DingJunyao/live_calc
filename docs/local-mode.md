# 本地模式（纯前端版）

生计有两种运行模式：

- **云端模式**（默认）：FastAPI 后端 + Vue 前端，多用户，数据存在服务端数据库。
- **本地模式**：纯前端应用，所有数据存储在浏览器 IndexedDB 中，无需任何后端服务。

本地模式适合只想在**单台设备**上使用、不想部署服务器的用户。构建产物是一个静态网站，可以放在任意静态服务器或直接通过 PWA 安装到桌面/手机。

> 本地模式为试验功能，强烈建议你在了解其与云端模式的差别之后，才决定是否使用。文档默认以云端模式的为准。

---

## 快速开始

### 1. 配置环境变量

在 `frontend/` 目录下创建或编辑 `.env` 文件：

```bash
# 开启本地模式
VITE_STORAGE_MODE=local

# 可选：GitHub 数据仓库的图片回退地址
VITE_DATA_REPO_IMAGE_BASE=https://raw.githubusercontent.com/DingJunyao/HowToCook_json/corr/out
```

> 未设置 `VITE_STORAGE_MODE` 时默认为 `cloud`（云端模式）。

### 2. 构建与运行

```bash
cd frontend
npm install
npm run dev      # 开发模式（含 PWA）
```

开发服务器启动后，打开 `http://localhost:5173` 即可看到初始化向导。

如果要部署，构建静态文件：

```bash
npm run build
# 产物在 frontend/dist/，用任意静态服务器托管即可
```

### 3. Docker 构建

在 Dockerfile 的构建阶段传入 `VITE_STORAGE_MODE`：

```bash
docker build --target frontend \
  --build-arg VITE_STORAGE_MODE=local \
  -t livecalc:local .
```

## PWA 支持

本地模式默认开启 PWA（渐进式 Web 应用）支持：

- **开发模式**：`VITE_STORAGE_MODE=local` 时自动启用 Service Worker，可测试 PWA 安装、离线访问、更新提示等完整体验。
- **生产构建**：任何模式的生产构建均包含 PWA（manifest、Service Worker、离线缓存）。
- **云端开发模式**：SW 关闭，避免改代码后刷新仍跑旧逻辑。

安装方式：

- **桌面端**：Chrome / Edge 地址栏右侧点击安装图标，或菜单 → 安装此应用。
- **移动端**：浏览器菜单 → 添加到主屏幕。

安装后以独立窗口运行，支持窗口控件覆盖（标题栏可拖动）、快捷方式直达各功能页。

> 提示：开发模式下 SW 可能缓存旧资源，遇到改代码不生效时，在浏览器 DevTools → Application → Service Workers 勾选「Update on reload」，或直接 Unregister 后刷新。

## 首次初始化

首次打开本地模式应用时，会自动跳转到初始化向导（`/setup`）。提供三种方式：

### 方式一：从 HowToCook 仓库导入

从 [HowToCook_json](https://github.com/DingJunyao/HowToCook_json) 数据仓库全量导入：

- 菜谱（含步骤、贴士、图片）
- 原料（含别名）
- 营养数据
- 计量单位

导入流程：

1. 获取仓库文件列表（GitHub Contents API）
2. 导入基础单位（恢复系统内置定义，再补充仓库新增单位）
3. 导入原料
4. 导入营养数据（失败可跳过）
5. 为每个原料创建对应商品
6. 逐批下载并导入菜谱（每批 10 个，单个失败重试 3 次后跳过）
7. 下载菜谱图片到 IndexedDB

> 全量导入包含数百个菜谱和大量图片，可能需要几分钟。导入过程中可以随时点击「停止导入」，已导入的数据会保留。

### 方式二：上传 ZIP 数据包

导入之前导出的 ZIP 备份文件。适合设备间迁移数据。

ZIP 文件结构应包含各数据表的 JSON 文件和 `recipes/` 目录下的独立菜谱文件。格式与云端模式导出兼容，两者可互导。

### 方式三：空白起步

只导入基础数据（15 个计量单位 + 13 个原料分类），不导入任何菜谱或原料。后续可在「数据维护中心」手动导入或创建。

|------|------|

| 单位管理 | 计量单位与换算关系 |
| 数据导入/导出 | ZIP 打包导出、ZIP 上传导入、GitHub 仓库导入 |

| 图片管理 | 上传、裁剪、本地 Blob 存储 |
| 图片存储配置 | IndexedDB 与 S3/OSS 存储后端切换、连接测试、迁移 |

### 本地模式隐藏/禁用的功能

| 功能 | 原因 |
|------|------|
| 用户注册/登录 | 单用户，自动以管理员身份登录 |
| 用户管理 | 无多用户需求 |
| 邀请码 | 无多用户需求 |
| 提议审核流程 | 单用户直接修改，无需审核 |
| SMTP/邮件配置 | 无邮件通知需求 |
| Claude Code Agent | 依赖服务器端 CLI，本地模式不可用 |

## 设置页（个人中心）

本地模式下「个人中心」改名为「设置」，页面分为以下几个区块：

- **个人偏好**：所在地区、默认单位（质量/体积/价格/能量）
- **数据备份**：数据导出、数据导入
- **数据规则**：单位管理、原料黑名单分组
- **系统集成**：地图配置（API 密钥）、AI 与机翻配置
- **图片管理**：图片存储配置（IndexedDB/S3 切换）、未使用图片清理
- **数据维护**：数据维护中心（菜谱导入、USDA 管理）、Agent 任务台

## 图片存储配置

本地模式默认将图片存储在浏览器 IndexedDB 中。如果需要将图片托管到 S3/OSS 对象存储（如阿里云 OSS、AWS S3、MinIO），可以在「设置 → 图片存储配置」中配置。

### 配置流程

1. 在「设置 → 图片管理 → 图片存储配置」中点击「切换存储后端」
2. 选择目标后端（IndexedDB 本地存储 或 S3 对象存储）
3. 填写 S3 配置（endpoint、bucket、region、密钥等）
4. 测试连接（浏览器向 S3 发送 HEAD 请求验证可达性）
5. 可选：迁移现有图片（IndexedDB 与 S3 之间）
6. 确认切换

### 注意事项

- S3 连接测试通过浏览器发起带 AWS SigV4 签名的 HEAD 请求，200/404 视为通过；403 表示密钥或权限有问题，网络错误通常是 CORS 未配置。
- 图片迁移使用 AWS SigV4 签名直传 S3 endpoint，不会往自定义 CDN 域名写入；请在存储桶 CORS 中允许 `PUT`/`HEAD`/`GET` 以及 `Authorization`、`Content-Type`、`x-amz-*` 请求头。
- 本地模式没有后端进程，图片迁移在浏览器内异步执行，任务进度通过 `import/task/:id` 轮询展示。
- 切换到 S3 后端后，图片 URL 会自动从 S3 endpoint 拼接（支持 path 风格、virtual-hosted 风格、自定义域名）。
- 切换到 S3 后端后，页面优先加载 S3 图片 URL；IndexedDB 中保留的旧 Blob 不再拦截远端图片显示。
- S3 密钥存储在浏览器 IndexedDB 的 system_config 中，不会上传到任何服务器。

## 未使用图片清理

在「设置 → 图片管理 → 未使用图片清理」中可以扫描并清理 IndexedDB 中不再被引用的图片：

- 打开页面后自动扫描，统计已用/未用图片数量和占用空间
- 未引用图片按创建时间分组（从未引用、180天以上、90至180天、60至90天、30至60天、30天内）
- 可勾选单张或整组图片进行删除
- 引用检测来源：菜谱的 images 数组、商品的 image_url 字段

## 数据备份

### 导出

在「设置 → 数据备份 → 数据导出」中：

- 选择导出范围（全部 / 仅我的数据）
- 系统将 IndexedDB 中的数据打包为 ZIP 文件下载
- 图片以二进制形式包含在 ZIP 中

### 导入

在「设置 → 数据备份 → 数据导入」中上传 ZIP 文件：

- 按依赖顺序写入（单位 → 分类 → 原料 → 商品 → 价格 → ...）
- 菜谱从 `recipes/` 目录逐个导入
- 导入格式与云端模式兼容

> 导出的 ZIP 也可以在云端模式中导入，反之亦然。

## AI Agent

本地模式内置浏览器原生 Agent，无需服务器进程：

1. 在「设置 → AI 与机翻配置」中填入 API Key
   - 支持 OpenAI 兼容接口和 Anthropic 兼容接口（不支持 Claude Code）
2. 在「设置 → Agent 任务台」中发起任务
3. Agent 通过预设的 IndexedDB 工具集操作数据（查询商品、菜谱、原料、更新营养等）
4. 大批量修改（>50 条）会弹出审批对话框，确认后执行

> Agent 的 API Key 存储在浏览器 IndexedDB 的 `system_config` 中，不会上传到任何服务器。API 请求从浏览器直接发送到 AI 服务商。

## 技术架构

### 数据层

- **存储引擎**：IndexedDB（浏览器原生，无需额外依赖）
- **数据库名**：`livecalc_local`
- **对象存储**：20+ 个 store，覆盖单位、原料、商品、价格、菜谱、商家、营养、图片等

### API 透明切换

前端代码统一调用 `api.get('/products')` 等接口。在 `api/index.ts` 中根据 `VITE_STORAGE_MODE` 环境变量决定：

- `local`：路由到 IndexedDB 本地处理器（`api/local/proxy.ts`）
- `cloud`：路由到 Axios HTTP 客户端

上层视图、Store、Composable 代码零改动。

### 业务逻辑移植

后端 Python 业务逻辑已完整移植为 TypeScript：

| 模块 | 对应后端 |
|------|---------|
| 成本计算 | `recipe_service.py` + `ingredient_price_service.py` |
| 单位换算 | `unit_conversion_service.py` |
| 营养聚合 | `nutrition.py` |
| 今日推荐 | `meal_recommender.py` |
| 商品加权 | `price_weighted.py` |
| 原料层级 | `hierarchy_resolver.py` |

## 限制与注意事项

1. **单设备单用户**：数据存在当前浏览器的 IndexedDB 中，不同浏览器/设备之间数据不共享。需手动导出/导入迁移。
2. **存储容量**：IndexedDB 通常有数百 MB 到数 GB 的配额（因浏览器而异）。导入大量菜谱图片后注意空间占用。
3. **清除浏览器数据**：清除浏览器缓存/数据可能删除 IndexedDB，导致数据丢失。请定期导出备份。
4. **网络依赖**：首次初始化（从 GitHub 导入）和地图、AI、USDA 数据下载需要网络连接。导入完成后核心功能可离线使用。
5. **隐私模式**：浏览器的隐私/无痕模式下 IndexedDB 可能被关闭时清除，不建议在隐私模式中使用。
6. **HTTPS 要求**：PWA 安装和 Service Worker 需要 HTTPS 环境（localhost 除外）。
7. **API Key 与敏感凭据的数据安全**：本地模式下，你在「设置」中填入的 AI 服务商 API Key、地图 Key、S3/OSS 凭据等会以**明文**存储在当前浏览器的 IndexedDB 中，且 AI 请求、S3 签名等操作均在浏览器内直接使用这些密钥。请知悉并自行承担以下风险：
   - 任何能在本应用同源运行的脚本（页面 XSS 漏洞、被污染的依赖、恶意浏览器扩展）都可能读取到这些长效凭据；
   - 建议为 S3/OSS 配置**最小权限的专用 IAM 子账户/STS 临时凭证**，而非主账户长效密钥，并设置用量/额度告警；
   - AI 服务商请使用**可单独限额、可随时吊销**的 Key，避免在浏览器中长期存放高额度主 Key；
   - 切勿在公共/不受信任的设备上使用本地模式，定期清理浏览器数据前请先在「数据备份」中导出，并注意导出文件同样含明文凭据；
   - 与云模式不同，本地模式没有服务端代你保管/代理这些密钥，安全性完全取决于你所在的浏览器环境。
